# Git module

The `git` module is exported through `flake.devModules.git` and included in the
default dev module group. It provides `git.*` options, uses the `file` module
for `.gitignore` and `.gitattributes`, and wraps `git` so hooks run without
editing `.git/config`.

## Options

<!-- markdownlint-disable MD013 -->

| Field                       | Type            | Default    | Description                                            |
| --------------------------- | --------------- | ---------- | ------------------------------------------------------ |
| `git.enable`                | bool            | `false`    | Enable the git integration.                            |
| `git.package`               | package         | `pkgs.git` | Git package wrapped by the shell.                      |
| `git.ignore.patterns`       | lines           | `""`       | Patterns added to the generated `.gitignore`.          |
| `git.ignore.templates`      | list of string  | `[]`       | Template names read from the `github-gitignore` input. |
| `git.attributes`            | lines           | `""`       | Contents of the generated `.gitattributes`.            |
| `git.hooks.<name>.enable`   | bool            | `true`     | Generate the hook named `<name>`.                      |
| `git.hooks.<name>.packages` | list of package | `[]`       | Packages available to `dev hook-<name>`.               |
| `git.hooks.<name>.commands` | commands        | `[]`       | Commands run by `dev hook-<name>`.                     |

<!-- markdownlint-enable MD013 -->

## Behavior

Ignore patterns and attributes are trimmed and written as authored. Gitignore
templates are read from `<name>.gitignore` in the `github-gitignore` flake
input, which is a non-flake input pointing at `github/gitignore`. Each template
gets a provenance comment. Patterns are written before templates, and both are
merged with patterns generated by the `file` module.

Each enabled hook is registered as `cli.commands.hook-<name>`. The hook scripts
are installed in a generated store directory and exec the installed `dev` CLI
with that subcommand. There is no per-hook package; the hook's `packages` are
installed as CLI subcommand packages.

When at least one hook is enabled, the module adds a wrapped `git` package in
place of the raw package. The wrapper sets `core.hooksPath` with
`GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0`/`GIT_CONFIG_VALUE_0`, so `.git/config` is
not modified. It also runs `git` through `bwrap` with the project root mounted
read-write. With no hooks, the raw `git.package` is added.

## Outputs

- `file.".gitignore".text` and `file.".gitattributes".text` on the evaluated
  shell.
- `cli.commands.hook-<name>` for each enabled hook.
- `passthru.git.hooks`: the generated hook directory, or `null`.
- `passthru.git.wrapper`: the wrapped `git` package, or `null`.
- The wrapped `git` package in `packages` when hooks are enabled; otherwise the
  raw `git.package`.
